# 轻映用户设置与快捷键配置设计

> 状态：已确认，待实施  
> 日期：2026-09-20  
> 范围：托盘设置入口、常规设置、快捷键设置、长截图限制设置  
> 本文只定义产品与技术设计，不包含业务代码修改。

## 1. 背景

轻映当前以 Windows 托盘程序运行，全局截图快捷键固定为 `Ctrl+Shift+Q`，长截图最大帧数固定为 30 帧，最大输出高度固定为 30000 像素。托盘菜单已经包含“开机自启”“允许本机 Agent 接口”和“退出”，但缺少统一的设置入口，也无法由用户修改快捷键和长截图限制。

本次设计为这些能力增加统一的用户设置窗口，同时保持项目现有的 C++17、Win32、轻量部署和低常驻资源方向。

## 2. 目标

1. 在轻映托盘右键菜单中增加“开始截图”和“设置…”入口。
2. 提供原生 Windows 设置窗口，集中管理常规、快捷键和长截图设置。
3. 允许用户修改全局截图快捷键，并可靠处理冲突、保存失败和运行时切换。
4. 允许用户修改长截图最大帧数和最大输出高度。
5. 复用现有开机自启与本机 Agent 开关，并保证托盘与设置窗口状态一致。
6. 配置在当前 Windows 用户范围内持久化，重启后生效。
7. 支持高 DPI、键盘导航和清晰的错误反馈。

## 3. 非目标

首版不包含以下内容：

- 不引入 Qt、Electron、WebView 或新的大型 UI 依赖。
- 不开放滚轮步长、滚动等待、重叠阈值、匹配容差和失败重试次数等算法参数。
- 不为复制、保存、编辑、钉图、长截图增加常驻系统级全局热键；复制和长截图控制仅允许在截图选区存续期间临时注册。
- 不实现账号同步、云端配置或远程配置。
- 不实现联网检查更新。
- 不借本功能重构现有 AutomationSettings、AutostartSettings 或整个 Application。

## 4. 当前代码事实

- 全局截图热键由 `HotkeyManager` 通过 `RegisterHotKey` 注册，默认修饰键为 `MOD_CONTROL | MOD_SHIFT`，按键为 `Q`。
- `Application` 接收 `WM_HOTKEY` 后投递 `WM_QINGYING_BEGIN_CAPTURE`，在 UI 线程启动截图流程。
- 长截图默认限制由 `LongShotLimits` 定义：`max_frames = 30`、`max_output_height = 30000`。
- 截图选区阶段已有以下临时快捷键：
  - `Esc`：取消截图或停止长截图；
  - `Tab / Shift+Tab`：切换智能选区候选；
  - `Ctrl+1 / Ctrl+2 / Ctrl+3`：元素识别、仅窗口、关闭智能选区；
  - `Ctrl+C`：复制截图；
  - `L`：开始、暂停或继续长截图。
- 标注阶段已有 `Ctrl+Z`、`Delete / Backspace`、`Esc` 和上下文相关的 `Enter`。
- 开机自启保存在 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`。
- 本机 Agent 开关由 `AutomationSettings` 保存在 `HKCU\Software\QingYing\Automation`。

## 5. 已选方案

采用“左侧导航 + 右侧内容 + 固定底栏”的原生设置窗口。

未采用的方案：

- 顶部标签页：实现简单，但后续页面增加时容易拥挤。
- 单页滚动布局：初期紧凑，但不利于容纳快捷键冲突说明和后续功能。

### 5.1 设计方向

视觉方向为“轻量工具型精致感”：低装饰、清晰分区、紧凑但不拥挤。主色延续轻映图标中的黄绿色，用于当前导航、焦点和成功状态；背景使用暖白色，分隔线使用低对比浅灰色。

区别于通用属性对话框的识别锚点是“快捷键胶囊”：组合键以独立键帽显示，例如 `Ctrl` `+` `Shift` `+` `Q`，同时承担录制、冲突和禁用状态的视觉表达。

设计可行性与影响指数 DFII：

- 视觉影响：3
- 场景契合：5
- 实施可行性：5
- 性能安全：5
- 一致性风险：2
- 总分：16，适合执行。

## 6. 托盘菜单

建议菜单顺序：

```text
开始截图        Ctrl+Shift+Q
────────────────────
设置…
开机自启        ✓
允许本机 Agent 接口
────────────────────
退出
```

行为规则：

- “开始截图”执行与全局截图热键相同的动作，右侧显示当前快捷键。
- “设置…”打开非模态设置窗口。
- 设置窗口只允许一个实例；重复点击时激活并置前已有窗口。
- 托盘开关与设置页双向同步。
- 保留托盘快捷开关，常用操作不强迫用户进入设置窗口。

## 7. 设置窗口框架

- 默认尺寸：720 × 540 逻辑像素。
- 最小尺寸：680 × 500 逻辑像素。
- 左侧导航宽度：168 逻辑像素。
- 右侧内容区水平内边距：32 逻辑像素。
- 页面：常规、快捷键、长截图。
- 底栏：恢复当前页默认值、取消、应用。
- 首版不持久化窗口位置和尺寸；每次在当前工作区内居中显示，避免引入与核心设置无关的屏幕拓扑迁移问题。
- 未发生修改时禁用“应用”。
- 关闭存在未应用修改的窗口时，提供“应用”“放弃”“返回设置”。

## 8. 常规页面

首版包含：

1. 开机时启动轻映。
2. 允许本机 Agent 接口。
3. 关于区域：产品名、版本号和“Windows 原生轻量截图工具”说明。

暂不增加没有稳定业务能力支撑的开关，例如“截图完成后自动复制”“保存后显示通知”。

规则：

- 系统设置仅在点击“应用”后改变。
- “恢复当前页默认值”把开机自启和本机 Agent 接口都改为关闭状态的草稿，仍需点击“应用”才生效。
- 写入或启动失败时恢复实际状态，并在对应字段附近显示错误。
- 设置窗口打开期间，如果用户从托盘修改开关，窗口应刷新基线。未修改的字段跟随外部状态；已修改的同一字段保留用户草稿并提示“系统状态已在外部更改，应用将使用当前选择”。

## 9. 快捷键页面

### 9.1 可编辑项

| 动作 | 默认值 | 作用域 | 是否允许清空 |
| --- | --- | --- | --- |
| 开始截图 | `Ctrl+Shift+Q` | 系统全局 | 否 |
| 复制截图 | `Ctrl+C` | 截图选区期间 | 是 |
| 长截图控制 | `L` | 截图选区期间 | 是 |

### 9.2 只读展示项

- `Tab / Shift+Tab`：切换选区候选。
- `Ctrl+1 / Ctrl+2 / Ctrl+3`：切换智能识别模式。
- `Esc`：取消或停止。

这些按键与截图状态机紧密耦合，首版不允许修改。

### 9.3 录制与校验

- 点击快捷键字段后进入录制状态，显示“请按下新快捷键”。
- `Esc` 取消本次录制；`Backspace` 或清除按钮清空允许为空的字段。
- 不接受只有修饰键的组合。
- 用户配置中的修饰键只允许 Ctrl、Shift、Alt、Win；`MOD_NOREPEAT` 由运行时附加。
- 全局截图键必须至少包含一个修饰键；截图过程快捷键允许使用单键。
- 空绑定统一编码为 `modifiers = 0` 且 `virtualKey = 0`；只空一半属于非法配置。
- 三个可编辑动作之间不允许使用相同组合，因为全局截图热键在选区期间仍保持注册。
- 拒绝把 Ctrl、Shift、Alt、Win 本身作为普通按键；拒绝输入法处理键和无法稳定显示名称的键。
- 明确拒绝 `Alt+Tab`、`Alt+Esc`、`Ctrl+Alt+Delete` 以及 Windows 明确保留的 Win 键组合；其余占用情况以 `RegisterHotKey` 结果为准。
- 三个可编辑快捷键都通过临时注册进行可用性预检。复制和长截图控制虽然只在截图期间生效，但由于遮罩窗口使用 `WS_EX_NOACTIVATE`，实现上仍需在截图期间临时调用 `RegisterHotKey`。
- 截图或长截图工作流活跃时，可以修改并应用常规项和长截图限制，但不能提交快捷键变化；页面显示“请结束当前截图后应用快捷键”。这是为了避免当前选区临时热键与待切换全局热键互相占用。
- 如果一个局部快捷键被改为“本事务成功后将释放的旧全局截图键”，预检把该冲突识别为本进程自占用并视为可用；其他 `RegisterHotKey` 失败仍按外部占用处理。这样允许一次操作完成合法的跨动作换键。
- 冲突时保留旧值，不允许应用，并显示冲突对象或“该快捷键已被其他程序占用”。
- 注册表只保存虚拟键码和修饰键位掩码，不保存本地化显示字符串。
- `MOD_NOREPEAT` 属于运行时注册策略，不写入用户配置。
- 设置保存后，如果其他程序在下一次截图前抢占了局部快捷键，则本次截图继续允许鼠标操作，并记录可诊断的注册失败；不得因为复制键或长截图键不可用而取消整个截图流程。

## 10. 长截图页面

| 设置项 | 默认值 | 允许范围 | 建议步进 |
| --- | ---: | ---: | ---: |
| 最大帧数 | 30 帧 | 2～60 帧 | 5 帧 |
| 最大输出高度 | 30000 像素 | 3000～60000 像素 | 5000 像素 |

页面同时只读展示以下安全保护：

- 到达页面底部时自动停止。
- 连续内容无变化时自动停止。
- 超过资源预算时自动停止。

这些保护始终启用，用户不能关闭。

交互规则：

- 超过 30 帧时提示“可能延长截取时间”。
- 超过 30000 像素时提示“宽页面可能占用较多内存”。
- 非数字、空值或越界输入不自动改写，显示字段错误并禁用“应用”。
- 设置修改只影响下一次长截图；正在运行的任务继续使用启动时的限制快照。
- 实际停止条件取帧数、高度、到底、无新增内容和资源预算中的最先到达者。
- 当前实现限制的是纵向输出高度，因此界面必须使用“最大输出高度”，不能写成含义不清的“最大像素”。

## 11. 配置模型与持久化

建议模型：

```text
UserSettings
├─ CaptureHotkey
│  ├─ modifiers
│  └─ virtualKey
├─ SelectionShortcuts
│  ├─ copy
│  └─ toggleLongShot
└─ LongShotLimits
   ├─ maxFrames
   └─ maxOutputHeight
```

新增注册表位置采用双槽快照，而不是把一次设置拆成多个可见值直接提交：

```text
HKEY_CURRENT_USER\Software\QingYing\Settings
├─ ActiveSlot      (REG_DWORD: 0 或 1)
├─ Slot0           (REG_BINARY: 完整的版本化设置快照)
└─ Slot1           (REG_BINARY: 完整的版本化设置快照)
```

规则：

- 保存时先把完整快照编码到非活动槽，读回并校验成功后再切换 `ActiveSlot`；进程中断发生在切换前时，旧槽仍然有效。
- 快照采用显式小端字段编码，不直接写入 C++ 结构体内存，避免填充和 ABI 差异。
- `UserSettingsStore::prepareSave()` 返回“准备结果 + `PreparedSettingsWrite`”。准备对象持有目标槽位；`commit()` 返回明确的 `SettingsStoreError` 并只负责切换 `ActiveSlot`，`cancel()` 和未提交析构均保持旧活动槽不变。不得以无返回值方式静默失败。
- 活动槽缺失、类型错误、校验失败或版本未知时，整份用户设置回退到安全默认值，同时保留错误诊断；不拼接来自不同快照的字段。
- 快照内部按逻辑组校验：单个快捷键绑定、整组选区快捷键、长截图限制。已知版本中的损坏逻辑组回退到该组默认值，随后再执行整体验证；如果仍有重复或非法组合，则整份设置回退默认值。
- `SchemaVersion` 首版为 1；高于当前版本的快照不尝试解释，直接使用默认值。以后新增版本必须提供显式迁移函数。
- 开机自启继续使用 Windows Run 项。
- Agent 开关继续使用现有 `AutomationSettings`。
- 配置只存放在当前用户范围，不请求管理员权限，不上传数据。

## 12. 组件与依赖

```text
托盘菜单 ───────────────┐
                       ▼
                 SettingsWindow
                 只负责界面和草稿
                       │ Apply
                       ▼
              SettingsApplicationService
              校验、应用、失败回滚
               ┌───────┼─────────┐
               ▼       ▼         ▼
        UserSettings  Hotkey   现有系统设置
        Store         Manager  Autostart / Agent
               │
               ▼
        LongShotLimitsProvider
               │ 每次任务开始取快照
               ▼
        LongShotController / Engine
```

职责：

- `SettingsWindow`：导航、控件、草稿、错误展示和未保存提示。
- `ShortcutBinding` 与 `SelectionShortcutSettings`：位于不依赖 `app` 的公共 UI 输入类型头文件中，供 app 与 overlay 同向依赖，禁止形成 `overlay → app` 反向依赖。
- `UserSettingsStore`：加载、校验、默认值回退和持久化。
- `SettingsApplicationService`：通过 `loadState()` 读取用户设置、开机自启和 Agent 的真实状态；通过 `apply()` 协调预检、保存、运行时切换和回滚，并返回提交后的真实状态。
- `HotkeyManager`：注册结构化键位；`prepareCaptureHotkey()` 返回只能提交一次的 RAII 预注册令牌，令牌析构或取消时释放新键。`commit()` 返回 `HotkeyCommitResult`：新键先成为唯一可路由的当前 ID，再尝试释放旧键；旧键注销失败时结果标记 `old_release_failed`，管理器保留旧 ID 但消息路由立即忽略它，并在下一次维护 tick、下一次设置应用和退出时重试清理。窗口显示非阻断警告。
- `LongShotLimitsProvider`：保存当前有效限制，并提供任务启动快照。
- `TrayController`：提供命令和回调，不拥有设置业务。
- `Application`：保持组合根职责，组装对象并路由消息。

## 13. 应用事务

用户点击“应用”后的顺序：

1. 校验全部草稿字段。
2. 如果快捷键发生变化且截图工作流活跃，拒绝快捷键部分并保持全部草稿；否则逐个预检。全局截图新组合由 RAII 令牌保持预注册，局部组合预检后立即释放；等于本事务旧全局键的局部组合按“自占用且将释放”处理。
3. `UserSettingsStore` 把新快照写入非活动槽并校验，但暂不切换活动槽。
4. 应用开机自启和 Agent 开关；每次成功都记录对应补偿动作。
5. 提交注册表活动槽。
6. 提交全局热键令牌：把新 ID 设为当前 ID，再释放旧键。
7. 更新 `LongShotLimitsProvider`，供下一次任务读取。
8. 重新读取真实状态，更新窗口基线并清除脏状态。

失败处理：

- 校验失败时不执行任何副作用。
- 热键预检失败时不保存，不释放旧热键。
- 快照准备失败时，RAII 令牌释放新热键，旧活动槽、旧热键和系统设置保持不变。
- 系统设置应用失败时，按与执行相反的顺序运行补偿动作，并放弃未提交快照。
- 活动槽提交失败时回滚已经改变的系统设置，并取消热键令牌。
- 热键提交不允许让新键失效，provider 更新必须为 `noexcept`；实现必须在进入步骤 5 前完成其所有可能失败的准备工作。`HotkeyCommitResult.old_release_failed` 只表示仍有待回收的 Windows 注册，旧 ID 必须从消息路由中立即失效，不能形成额外业务入口；管理器按维护 tick、下次应用和退出三个时机重试清理。
- 如果补偿回滚也失败，调用 `loadState()` 重读真实状态，在窗口顶部列出失败项；成功项和失败项都不得伪装成旧状态或已保存状态。

应用启动时，如果已保存的全局热键被其他程序占用，轻映继续启动并保留托盘“开始截图”入口，不覆盖用户保存值。设置页把该键标记为当前不可用并引导用户修改；本次进程不静默回退并持久化另一个按键。

## 14. 错误与状态反馈

- 普通字段错误在字段下方就地显示。
- 页面级保存错误显示在内容区顶部横幅。
- “应用”成功后在底栏短暂显示“设置已保存”。
- 热键状态必须同时使用图标、文字和颜色，不能只依赖红绿。
- Agent 接口启动失败、开机自启写入失败和注册表写入失败均使用中文信息。
- 不可恢复的内部错误才使用模态对话框。

## 15. 可访问性与 DPI

- 支持 `Tab / Shift+Tab` 按视觉顺序移动焦点。
- `Space` 切换开关，方向键切换左侧页面。
- 快捷键录制期间，`Enter` 不触发“应用”。
- `Esc` 优先退出快捷键录制，其次尝试关闭设置窗口。
- 100%、125%、150%、200% 缩放下文字和控件不得截断。
- 高对比度模式下保持可识别的焦点、选择和错误状态。
- 控件提供可访问名称、当前值、单位和错误说明。

## 16. 性能、可靠性和维护约束

- 设置窗口打开过程不创建后台线程。
- 设置窗口关闭后不保留 HWND、字体、画刷或其他 GDI 资源。
- 常驻配置对象规模固定，不显著增加托盘空闲内存。
- 全局热键切换路径保持快速，不在 `WM_HOTKEY` 回调中进行注册表操作。
- 长截图限制按任务快照传递，不允许工作线程读取变化中的 UI 草稿。
- 注册表句柄、字体、画刷和临时热键必须使用明确生命周期管理。
- C++ 实现遵守项目 Allman 风格、RAII、宽字符 Win32 API 和现有命名规范。

## 17. 验收标准

1. 托盘可以直接开始截图并打开设置窗口。
2. 重复点击“设置…”只激活一个窗口。
3. 修改全局热键后不重启即可使用。
4. 热键冲突或保存失败时，旧热键仍然有效。
5. 重启应用后恢复已保存设置；若保存的全局热键此时被占用，应用仍进入托盘并保留鼠标截图入口。
6. 复制与长截图局部快捷键可以修改或清空，并只在截图选区期间响应。
7. 长截图运行中修改限制不影响当前任务，只影响下一次任务。
8. 托盘开关与常规页状态一致。
9. 损坏或越界配置不会阻止应用启动，会回退到安全默认值。
10. 所有错误信息为中文且能指向具体字段或操作。
11. 100%～200% DPI 下布局可用，键盘可以完成全部设置操作。
12. 关闭窗口、退出应用、系统关机或 Explorer 重启时，不泄漏热键、窗口、注册表句柄、GDI 对象或工作线程。

## 18. 风险与缓解

| 风险 | 影响 | 缓解措施 |
| --- | --- | --- |
| 新热键被其他程序占用 | 用户失去截图入口 | 新键成功注册后才释放旧键 |
| 多项设置部分成功 | 界面与系统状态不一致 | 统一应用服务、补偿回滚、失败后重新读取真实状态 |
| 长截图上限过高 | 内存增长或等待时间过长 | 有界输入、资源预算优先、超推荐值警告 |
| 运行中改变限制 | 数据竞争或一次任务使用两套参数 | 任务启动时复制不可变快照 |
| 原生自绘窗口复杂 | DPI、焦点或资源管理缺陷 | 布局与绘制纯函数测试、RAII、真实 DPI 人工验收 |
| 配置格式演进 | 旧版本数据无法读取 | SchemaVersion、显式迁移和未知版本整份回退 |

## 19. 决策记录

| 决策 | 备选方案 | 选择原因 |
| --- | --- | --- |
| 使用左侧导航设置窗 | 顶部标签、单页滚动 | 扩展性与中文信息密度更合适 |
| 使用 Win32 原生界面 | Qt、Electron、WebView | 保持轻量部署和现有技术栈 |
| 显式“应用”生效 | 控件即时生效 | 支持多项校验、冲突预检和取消修改 |
| 首版开放三个快捷键 | 所有快捷键均可编辑 | 控制冲突复杂度，覆盖高价值动作 |
| 长截图只开放两个上限 | 开放全部算法参数 | 普通用户可理解，降低拼接失败风险 |
| 安全保护不可关闭 | 提供高级开关 | 防止无限截取和资源失控 |
| 使用 HKCU 注册表 | JSON 配置文件 | 与现有设置方式一致，无权限和路径问题 |
| 任务读取限制快照 | 工作线程实时读取设置 | 避免数据竞争并保证单次任务行为一致 |
| 保留托盘快捷开关 | 全部移动到设置窗口 | 保持常用操作效率 |
