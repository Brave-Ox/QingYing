# 浏览器外壳智能吸附优化设计

> 状态：已确认，待实施  
> 日期：2026-09-21  
> 范围：Chromium 浏览器标签栏、地址栏、书签栏、工具栏及其小部件  
> 本文只定义设计，不包含业务代码修改。

## 1. 背景

轻映当前已经具备“窗口快照/已知内容与视觉发现 + 后台 UIA/MSAA + 候选评分 + 悬停稳定”的智能吸附链路，也已经实现 UIA `BuildCache`、后台结果 `PostMessage` 通知、近邻结果复用、视觉缓存及 Chromium 浏览器外壳上下文。但浏览器顶部外壳仍存在两个可感知问题：首次精确候选出现较慢；鼠标在相邻标签、书签和插件按钮之间移动时，高亮框不够跟手。

当前统一的 16ms 更新节流和部分候选间 48ms 稳定延迟会进入浏览器路径。UIA CacheRequest 同时读取名称及多种 Pattern，点命中不能归属根窗口时还会立即执行 Root Scoped Traversal。这些设计保证了通用性，但让浏览器外壳的慢路径参与得过深。

## 2. 目标

1. 鼠标进入浏览器外壳后立即出现安全的粗粒度高亮框。
2. BrowserShellAtlas 命中时近乎即时显示标签页、书签、插件按钮等完整点击区域。
3. 精确 UIA 结果异步到达后，无闪烁地替换粗框或缓存框。
4. 支持插件按钮、书签、书签文件夹、标签页、标签关闭按钮、地址栏及常用工具栏按钮。
5. 将 Root Scoped UIA/MSAA 深遍历移出鼠标移动热路径。
6. 不改变 VSCode、PyCharm 和其他应用的默认候选链、阈值及稳定器行为。
7. 用 P50/P95 数据和真实应用矩阵验证收益，不用主观感受代替测量。

## 3. 非目标

- 不删除 UIA/MSAA，也不改成纯视觉优先。
- 不引入 OCR、OmniParser、全屏 Canny 或新的第三方运行时。
- 不长期持有或跨线程传递 `IUIAutomationElement*`。
- 不依赖浏览器扩展、CDP 或远程调试端口。
- 不在本次优化中重写 VSCode/PyCharm 的 Electron Workbench 视觉策略。
- 不在缺少实测数据时直接全局缩短 16ms、48ms、80ms 或120ms参数。

## 4. 已确认约束与假设

- 平台为 Windows，使用现有 C++17、Win32、UIA、MSAA 和固定容量数据结构。
- UI 线程只读取窗口快照和不可变几何缓存，不执行跨进程 UIA。
- 首帧优先于首帧精确度；允许先显示 BrowserChrome、Toolbar 或 Client 粗框。
- 精确候选一旦仍覆盖鼠标，不得被晚到的粗回退覆盖。
- 缓存失效时必须安全退回现有 Window/Client/KnownContent 链路。
- 实际阈值以重复测量校准，本文给出的时间仅是初始实验值。

## 5. 方案比较

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 仅调整节流和稳定延迟 | 改动小 | 治标不治本，容易放大闪烁并影响其他应用 | 不采用 |
| BrowserShellAtlas + 分级精化 | 热命中快、精度可逐步提高、可隔离浏览器行为 | 需要缓存失效和展示状态机 | 采用 |
| 长期维护完整 UIA 事件树 | 热路径理论上最快 | UIA 事件可靠性、COM 生命周期和浏览器版本兼容成本高 | 暂缓 |

## 6. 总体架构

```text
WM_MOUSEMOVE
    |
    +-- UI Snapshot ---------------------------------- UI线程
    |      +-- 立即展示 Client / BrowserChrome 粗框
    |
    +-- BrowserShellAtlas::hitTest ------------------- UI线程
    |      +-- 命中后立即展示缓存控件
    |
    +-- DiscoveryWorker ------------------------------ 后台
    |      +-- 已知内容 / 浏览器顶部有限 ROI 视觉
    |
    +-- AccessibilityWorker -------------------------- 后台MTA
    |      +-- FastPoint
    |      +-- LocalSemantic + 有限同级预取
    |
    +-- RefinementWorker ----------------------------- 后台MTA
           +-- 停留后 Root Scoped UIA / 深层 MSAA
```

浏览器专属路径只在 `SmartRegionWindowSnapshot::is_chromium_browser_chrome` 为真时启用。其他应用继续使用现有链路。

## 7. 浏览器外壳角色

```cpp

  NewTabButton,

  ReloadButton,
  AddressBar,
  Bookmark,
  BookmarkFolder,
  ExtensionButton,
```

插件图标等视觉 glyph 不能直接视为控件边界。UIA 可用时使用 Button 的完整 `BoundingRectangle`；只有 UIA 不可用时，才允许依据工具栏行高、相邻间距和独立边缘把 glyph 扩展为控件单元格。

## 8. BrowserShellAtlas

Atlas 是截图会话内的不可变几何快照，不是长期 UIA 元素树。

```cpp
enum class BrowserShellSource : std::uint8_t
{
  Geometry,
  Visual,
  UiaFast,
  UiaSemantic
};

struct BrowserShellContext
{
  HWND m_root_window{nullptr};
  DWORD m_process_id{0};
  WindowRect m_window_rect;
  UINT m_dpi{96};
  std::uint64_t m_capture_session_generation{0};
  std::uint64_t m_window_generation{0};
  bool m_full_screen{false};
};

struct BrowserShellEntry
{
  WindowRect m_hit_rect;
  BrowserShellRole m_role{BrowserShellRole::Unknown};
  BrowserShellSource m_source{BrowserShellSource::Geometry};
  std::uint8_t m_confidence{0};
  std::uint64_t m_updated_at_ms{0};
  std::uint64_t m_identity_hash{0};
  std::uint32_t m_row_id{0};
};

struct BrowserShellAtlasSnapshot
{
  static constexpr std::size_t MaximumEntries = 64;

  BrowserShellContext m_context;
  std::array<BrowserShellEntry, MaximumEntries> m_entries{};
  std::size_t m_entry_count{0};
  std::uint64_t m_layout_generation{0};
};
```

每个快照最多保存64条记录。命中选择依次考虑：必须包含鼠标、精确来源优先、可操作角色优先、面积更小者优先、更新时间更新者优先。所有矩形均为屏幕物理像素并使用左/上闭、右/下开的区间。

合并优先级为：`UiaSemantic > UiaFast > Visual > Geometry`。低质量结果不得覆盖仍有效的高质量结果。相同身份的矩形仅有不超过2个物理像素的边缘变化时可以忽略，以避免抖动。

`identityHash` 只用于快速缩小比较范围，不能单独证明身份相同。哈希输入为窗口代际、布局代际、行ID、角色、可用的AutomationId/Name哈希及量化矩形；发生哈希相同时，还必须比较角色、行ID以及矩形关联。跨布局代际的记录不视为同一身份。

### 8.1 角色映射

| 容器/位置 | ControlType与语义 | 角色 |
|---|---|---|
| TabStrip | TabItem | Tab |
| TabStrip内、位于Tab右侧小区域 | Button + Invoke | TabCloseButton |
| TabStrip末端 | Button + Invoke，且不属于已有Tab | NewTabButton |
| Toolbar左侧导航组 | Button + Invoke | BackButton/ForwardButton/ReloadButton；无法可靠区分时保持Unknown Button |
| Toolbar中部宽Edit/ComboBox | Value或可聚焦 | AddressBar |
| Toolbar地址栏右侧、菜单按钮左侧 | Button + Invoke/Toggle | ExtensionButton |
| Toolbar右端 | Button + Invoke | ProfileButton/MenuButton；语义不足时保持Unknown Button |
| BookmarkBar | Hyperlink或Button + Invoke | Bookmark |
| BookmarkBar | Button/MenuItem + ExpandCollapse | BookmarkFolder |

角色分类必须同时使用容器行、相对位置、ControlType和必要Pattern。仅凭Name文本或图标像素不得判定具体角色；无法可靠细分时保留可操作的Unknown角色和准确矩形，不编造插件或菜单语义。

### 8.2 失效

整表失效：HWND/PID改变、窗口销毁、DPI变化、全屏状态变化、窗口矩形任一边变化或截图会话结束。窗口平移/缩放后的Atlas可在后续版本加入坐标变换复用，首版直接失效以保证正确性。

布局代际递增并后台重建：标签增删/重排、书签栏显隐、扩展按钮增减、垂直标签页模式变化；或者同一16×16逻辑像素量化单元内，缓存矩形覆盖鼠标但连续3次FastPoint均确认属于其他控件。逻辑像素按照当前DPI换算为物理像素，量化单元在窗口或布局代际变化时复位。

单条淘汰：UIA确认控件消失；同角色、同行的新矩形与旧矩形无交集；或者当前点连续2次FastPoint确认属于其他控件。任一成功确认会清零该条目的失败计数。

不使用几百毫秒的短TTL周期性清空整表。初始软过期时间为2000ms；软过期条目仍可用于首帧，但必须提交后台FastPoint校验，校验失败后再移除。该数值属于实验参数，任务7根据命中率和错误率决定是否调整。

### 8.3 线程模型

后台线程构建可变 Atlas，随后通过 `makeSnapshot()` 生成 `std::shared_ptr<const BrowserShellAtlasSnapshot>`。C++17实现使用 `std::atomic_store()` 和 `std::atomic_load()` 操作普通 `shared_ptr` 对象，不使用C++20的 `std::atomic<std::shared_ptr<T>>`。

现有完成消息只负责唤醒UI线程，快照所有权保存在worker受锁保护的结果槽中；消息的 `WPARAM/LPARAM` 不携带拥有型裸指针。Overlay销毁先关闭接收标志、停止并join worker，再释放结果槽，晚到消息只读取失效令牌并返回。快照只包含普通值，不包含COM接口指针。

## 9. 两阶段 UIA

### 9.1 FastPoint

只缓存 `BoundingRectangle`、`ControlType`、`IsControlElement`、`IsContentElement`、`IsEnabled` 和 `NativeWindowHandle`。执行点命中及最多4层父级遍历，不读取 Name、AutomationId、HelpText 或 Pattern。

Button、TabItem、MenuItem、Hyperlink、Edit、ComboBox 可直接形成候选；Pane、Group、Custom 只能成为行或容器回退。初始应用层预算为16～24ms，单次跨进程调用仍受现有 UIA connection/transaction timeout 保护。

### 9.2 LocalSemantic

仅在需要确认无名称按钮、区分书签文件夹、建立行级 Atlas 或补充身份时执行。按 ControlType 读取必要属性：

| ControlType | 属性或 Pattern |
|---|---|
| Button | Name、AutomationId、Invoke、Toggle |
| TabItem | Name、SelectionItem、Invoke |
| MenuItem | Name、Invoke、ExpandCollapse |
| Hyperlink | Name、Invoke |
| Edit/ComboBox | Name、Value、ExpandCollapse |
| Pane/Group | 默认不读取 Pattern |

找到可信 Toolbar、TabStrip 或 BookmarkBar 后，只对一层直接子元素执行有限 `FindAllBuildCache(TreeScope_Children)`。最多读取64个子项，只保留与目标行相交的有效矩形，不递归孙节点。FastPoint先返回ControlType，再选择对应的语义CacheRequest并通过 `BuildUpdatedCache` 或下一次 BuildCache 调用读取必要属性，避免一套请求预取全部Pattern。

### 9.3 DeepRefinement

只有Chromium浏览器外壳中，同一16×16逻辑像素量化区域停留约120ms、Atlas/FastPoint/LocalSemantic/局部视觉均未提供可信局部控件，且窗口及布局代际未变化时，才提交 Root Scoped UIA 或深层 MSAA。每个窗口/布局/量化单元最多提交一次，鼠标离开单元或任一代际变化后复位。它必须运行在拥有独立线程和MTA会话的 RefinementWorker，不能阻塞 FastPoint。非Chromium应用继续使用现有 `locate()` 和MSAA回退行为，本次不迁移其深遍历。

## 10. 小部件准入规则

| 类型 | 初始最小尺寸 | 必要背书 |
|---|---:|---|
| Button/MenuItem | 12×12 | ControlElement且启用 |
| TabItem | 16×16 | 位于浏览器顶部且包含鼠标 |
| Hyperlink/Bookmark | 12×12 | 有名称或Invoke |
| BookmarkFolder | 12×12 | ExpandCollapse或菜单语义 |
| Edit/AddressBar | 24×16 | Value或可聚焦 |
| 纯视觉图标 | 不直接接受glyph | 必须扩展为可信工具栏单元格 |
| Pane/Group/Custom | 32×24 | 只能作为区域回退 |

这些规则只应用于 Chromium 外壳，不降低全局视觉阈值。

## 11. 无闪烁展示状态机

展示分为 `Coarse`、`Cached`、`Exact`。候选发现和展示决策分离。

```cpp
enum class BrowserPresentationLevel : std::uint8_t
{
  Coarse,
  Cached,
  Exact
};

enum class BrowserPresentationAction : std::uint8_t
{
  Keep,
  Apply,
  Defer,
  Clear
};

enum class BrowserPresentationReason : std::uint8_t
{
  None,
  FirstCandidate,
  HigherQuality,
  CurrentNoLongerContainsPoint,
  AdjacentCandidatePending,
  StaleGeneration,
  StalePointerSequence,
  LowerQualityFallback,
  FastMotion
};

struct BrowserPresentationToken
{
  std::uint64_t m_window_generation{0};
  std::uint64_t m_layout_generation{0};
  std::uint64_t m_pointer_sequence{0};
};

struct BrowserPresentedCandidate
{
  SmartRegionCandidate m_candidate;
  BrowserPresentationLevel m_level{BrowserPresentationLevel::Coarse};
  BrowserPresentationToken m_token;
  WindowRect m_display_rect;
  WindowRect m_hit_rect;
};
```

状态机对象持有当前候选、相邻候选连续命中计数、延迟开始时间和取消令牌；决策结果包含 `Keep/Apply/Defer/Clear`、延迟及诊断原因。

| 切换 | 初始延迟 |
|---|---:|
| 无候选 → 任意有效候选 | 0ms |
| Coarse → Cached/Exact | 0ms |
| Cached → 同一控件Exact | 0ms |
| 当前矩形不再包含鼠标 | 0ms |
| Atlas控件A → Atlas控件B | 8～16ms或连续两次采样 |
| UIA控件A → UIA控件B | 12～24ms |
| Exact → Visual | 24～32ms |
| 局部控件 → Toolbar/Window | 32～48ms |
| 鼠标仍在Exact内，晚到粗候选 | 禁止切换 |

异步结果必须通过 HWND、PID、窗口矩形、窗口代际、布局代际、结果年龄和当前点包含关系校验。指针序号分成两条通道：旧序号结果在窗口和布局代际有效时可以更新Atlas，但绝不能直接展示；减速后必须对最新Atlas重新 `hitTest`，生成携带当前指针序号的新展示候选。只有当前序号结果才能直接进入展示状态机。

展示初始使用3个逻辑像素的退出容差，按DPI转换成物理像素；点击确认必须使用真实 `hitRect` 重新命中，不能使用扩大后的显示矩形。

“一次可见替换”定义为：已绘制后，角色变化或任一矩形边变化超过2个物理像素并触发Overlay重绘。UiSnapshot和Atlas命中在同一次 `updateHover()` 中完成选择后只绘制一次；冷Atlas显示Coarse后，FastPoint的准确矩形允许一次替换；同身份LocalSemantic只更新元数据和Atlas，默认不再次重绘。若语义阶段发现FastPoint矩形错误，只更新Atlas供下一次命中使用并记录纠错诊断。

## 12. 性能与可靠性目标

以下为初始验收目标，实测后允许通过决策记录调整：

- 首个粗框 P95 ≤ 16ms。
- Atlas `hitTest` P95 ≤ 1ms。
- Atlas 命中不得启动视觉扫描。
- 精确 UIA 暖命中展示 P95 ≤ 50ms；冷命中 P95 ≤ 100ms。
- 同一控件从首次绘制到FastPoint精确框最多产生一次按上述口径定义的可见替换。
- UI线程无跨进程 UIA 调用。
- 快速移动期间旧候选不得长期覆盖当前鼠标。
- 关闭 Overlay 后不得应用晚到结果，不得泄漏 COM、HANDLE、GDI 或 USER 对象。

## 13. 回归门禁

- Chrome/Edge：标签、关闭按钮、新建标签、地址栏、前进/后退/刷新、插件、书签、书签文件夹、菜单。
- VSCode：编辑器、终端、侧栏、标签、底部面板。
- PyCharm：编辑器、项目树、终端、工具窗口、标签。
- 其他：Windows Terminal、记事本、资源管理器、普通 Qt/Win32。
- 环境：100%/125%/150% DPI、多屏、负坐标、窗口移动、最大化、全屏、快速移动和快速点击。

VSCode/PyCharm 任一目标从局部元素退化为 Client/Window，立即停止后续扩展并优先修复回归。

## 14. 决策记录

1. 选择浏览器专属 Atlas，不修改通用应用默认策略，因为浏览器顶部布局稳定且相邻访问概率高。
2. 选择“首帧粗框、缓存快框、UIA精确框”，接受冷启动短暂出现粗框，以换取立即反馈。
3. 选择两阶段 UIA，避免每次点命中读取 Name 和全部 Pattern。
4. 选择有限同级预取，不缓存完整 UIA 树，以控制跨进程调用和失效复杂度。
5. 选择独立 RefinementWorker，使深遍历不能阻塞实时查询。
6. 选择浏览器专属展示状态机，保留现有通用稳定器以保护 VSCode/PyCharm。
7. 暂不采用完整 UIA 事件树、OCR、模型和浏览器扩展；只有实测证明当前方案不足时重新评估。

## 15. 重新评估触发条件

- Chrome/Edge 更新后，有限 UIA 路径持续无法获得工具栏直接子元素。
- Atlas 实际命中率低于预期，维护成本高于减少的 UIA 调用成本。
- 精确候选 P95 仍超过100ms，且证据表明瓶颈不是稳定器或 UIA 属性过取。
- UIA 事件订阅能够在目标浏览器版本中稳定提供布局失效信号。
