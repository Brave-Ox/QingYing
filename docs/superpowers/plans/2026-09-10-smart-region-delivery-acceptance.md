## 任务 16：性能、资源和完整交付验收

执行命令：

```powershell
.\tools\measure_release_acceptance.ps1 -TrialCount 30 -IdleSeconds 60 -TrialTimeoutMilliseconds 2000
```

测量方法：

1. 启动与生产程序使用相同应用及 Overlay 库的 Release 测试隔离进程。
2. 首次唤起作为预热，不计入 P95。
3. 关闭 Overlay 后空闲 60 秒，记录工作集及 HANDLE/GDI/USER 基线。
4. 向托盘窗口投递与全局热键相同的 `WM_HOTKEY` 消息，轮询只读首帧查询消息；仅在首个 `UpdateLayeredWindow` 成功提交后停止计时。
5. 连续执行 30 次并取 nearest-rank P95，随后比较线程、HANDLE、GDI 和 USER 资源计数；资源查询失败会直接判定脚本失败。

| 隔离夹具预热后空闲 60 秒工作集 | 18,108,416 字节（17.270 MiB） | 不超过 40 MiB | 通过 |
| 热键消息到 Overlay 首帧平均值 | 91.859 ms | 记录项 | 通过 |

| 30 次循环 HANDLE 增量 | 0 | 应稳定 | 通过 |
| 30 次循环线程增量 | 0 | 应稳定 | 通过 |
| 30 次循环 GDI 对象增量 | 0 | 应稳定 | 通过 |

说明：上述首帧数据来自隔离夹具，从应用收到 `WM_HOTKEY` 开始计时，不包含 Windows 从物理键盘生成并投递热键消息的系统级延迟，也不代替正式进程在用户配置和真实桌面下的测量。UIA 在专用工作线程执行，专项测试验证提交不阻塞、突发请求合并、清理后晚结果丢弃、失败冷却和缓存复用。30 次循环只能确认本轮线程、HANDLE、GDI 和 USER 计数未增长，不能单独证明不存在 COM 或长期资源泄漏。连续移动的视觉流畅度、真实应用命中质量和多显示器行为仍必须由人工矩阵确认。
