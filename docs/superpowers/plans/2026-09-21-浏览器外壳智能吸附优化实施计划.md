# 浏览器外壳智能吸附优化实施计划

> **For agentic workers:** 实施时按任务顺序逐项执行；每项先补失败测试，再做最小实现，再运行专项与保护性回归。未经用户明确要求，不执行任何 Git 暂存、提交、推送、重置、变基或 stash 操作。

**目标：** 在不改变 VSCode、PyCharm 和其他应用默认识别逻辑的前提下，实现浏览器外壳首帧立即反馈、Atlas 近即时命中及 UIA 精确结果无闪烁替换。

**架构：** Chromium 外壳通过独立策略进入 BrowserShellAtlas 快路径。后台 AccessibilityWorker 分别执行 FastPoint 和 LocalSemantic，独立 RefinementWorker 只在停留后运行深遍历；UI线程通过不可变快照和展示状态机消费结果。

**技术栈：** Windows、C++17、Win32、Microsoft UI Automation、MSAA、GoogleTest、CMake、现有固定容量候选与后台工作线程。

## 全局约束

- 遵守项目 C++ Allman 风格、RAII、`m_` 成员前缀和 `std::array::at()` 边界检查要求。
- 不引入第三方运行时，不跨线程传递 COM 接口，不在 UI 线程执行 UIA。
- 新行为必须由 Chromium 外壳上下文显式启用。
- 任何任务导致 VSCode/PyCharm 局部候选退化，停止后续任务并修复。
- 时间阈值是实验默认值；只有测量证明收益超过运行噪声后才能固化。
- 自动化结果和真实应用人工结果必须分开记录，不得把未执行项写为通过。
- 构建前置条件以根目录 `README.md` 和 `build.bat` 为准：Visual Studio 2019 C++工具链、x64、仓库同级 `../thirdparty_install/vcpkg` 及 `gtest:x64-windows`。
