# F1 自定义区域与标注功能分工指南

> 目的：指导 F1“完整自定义区域截图”和 P1“截图标注”并行开发，减少对 `SelectionOverlay`、`Application` 和共享图片契约的修改冲突。

## 1. 当前基线

当前项目已经具备：

- 全屏截图遮罩；
- 鼠标拖拽框选；
- 选区矩形归一化；
- 区域截图；
- 选区操作条；
- 复制和 PNG 保存入口。

当前仍缺少：

- F1 的八点调整、移动选区、完整 DPI/多屏适配；
- 标注文档、标注渲染、撤销/重做；
- “编辑”按钮到标注编辑器的完整接线。

## 2. 总体流程

```text
热键
  ↓
SelectionOverlay：创建选区
  ↓ SelectionResult
Application：CaptureRegion
  ↓ Image（BGRA32，物理像素）
SelectionAction::Edit
  ↓
AnnotationOverlay：编辑标注
  ↓ 合成后的 Image
SelectionAction::Copy / Save / Pin
  ↓
  ActionDispatcher → Export / PinManager
```

硬性边界：

1. F1 负责“选取哪一块屏幕区域”，不负责标注对象；
2. 标注负责“如何修改截图结果”，不直接捕获屏幕；
3. `Application` 负责两个模块之间的流程编排；
4. Copy、Save、Pin 等业务动作继续经 `ActionDispatcher` 执行。

## 3. 第一人：F1 完整区域截图

### 3.1 第一人职责

第一人负责：

- `SelectionController` 状态机；
- 八点调整手柄；
- 已选区域移动；
- 选区边界和最小尺寸校验；
- 取消、重新选择和操作条前的选区状态；
- 逻辑坐标到物理像素坐标的转换；
- 单屏、多屏、125%/150% DPI 冒烟验证。

### 3.2 第一人建议修改范围

允许主要修改：

```text
include/qingying/overlay/selection_controller.hpp
src/overlay/selection_controller.cpp
include/qingying/overlay/selection_overlay.hpp
src/overlay/selection_overlay.cpp
新增 overlay/selection_handles.*
新增 overlay/coordinate_transform.*
```

F1 不应修改：

- `AnnotationEngine` 的数据模型；
- `ExportService` 的 PNG/剪贴板实现；
- `CaptureEngine` 的像素编码逻辑；
- MCP、口令和 Pin 模块。

### 3.3 第一人输出契约

选区确认后产生 `SelectionResult`：

```cpp
struct SelectionResult {
  bool cancelled;
  int x;
  int y;
  int width;
  int height;
  SelectionAction action;
};
```

约定：

- `x/y/width/height` 进入 `CaptureEngine` 前必须是物理像素；
- `width` 和 `height` 必须大于 0 才能确认；
- 反向拖拽必须归一化；
- F1 不在结果中写入标注对象。

### 3.4 第一人验收

- 可以拖拽出矩形；
- 可以拖动任意一个边或角调整大小；
- 可以拖动整个选区移动；
- Esc 和右键可以取消；
- 选区不会超出有效桌面范围；
- 单屏和双屏下截图位置正确；
- 125%/150% DPI 下选框与截图内容没有明显偏移；
- 原有复制、保存操作不回归。

## 4. 第二人：标注功能

### 4.1 第二人职责

第二人负责：

- 标注对象数据模型；
- 标注工具状态；
- 鼠标绘制预览；
- 标注提交；
- 撤销/重做；
- 标注对象栅格化；
- 标注编辑器窗口或覆盖层。

### 4.2 第二人建议新建文件

标注尽量以新增文件为主，避免和 F1 修改同一实现文件：

```text
include/qingying/annotate/annotation_types.hpp
include/qingying/annotate/annotation_document.hpp
include/qingying/annotate/annotation_engine.hpp
include/qingying/annotate/annotation_renderer.hpp
src/annotate/annotation_document.cpp
src/annotate/annotation_engine.cpp
src/annotate/annotation_renderer.cpp
include/qingying/overlay/annotation_overlay.hpp
src/overlay/annotation_overlay.cpp
tests/annotation_document_test.cpp
tests/annotation_renderer_test.cpp
```

现有 `AnnotationEngine` 只有 `clear()`，第二人可以在保持类名不变的前提下扩展接口。

### 4.3 第二人标注对象模型

建议第一版支持：

```cpp
enum class AnnotationType {
  Rectangle,
  Ellipse,
  Arrow,
  Pen,
  Text,
  Mosaic,
};
```

对象几何信息建议使用截图内部坐标：

- 矩形、椭圆：`RectF`；
- 箭头：起点和终点；
- 画笔：点序列；
- 文字：起点、文本、字体样式；
- 马赛克：矩形区域和块大小。

统一样式至少包含：颜色、线宽、不透明度、字体大小。

### 4.4 第二人标注坐标契约

标注坐标必须相对于截图左上角，而不是桌面坐标：

```text
截图 Image
(0, 0) ─────────────→ width
  │
  │     标注对象坐标
  │
  ↓
height
```

编辑器显示截图时可以缩放，但只在显示层做：

```text
屏幕坐标 ↔ 编辑器视图坐标 ↔ Image 物理像素坐标
```

标注数据最终必须落在 Image 物理像素坐标中，便于复制、保存和钉图复用。

### 4.5 第二人标注引擎职责

`AnnotationEngine` 不应该直接操作窗口消息，也不应该直接调用 `ActionDispatcher`。

建议职责：

```cpp
class AnnotationEngine {
 public:
  void clear();
  void add(const Annotation& annotation);
  bool undo();
  bool redo();
  Image render(const Image& source) const;
};
```

原始截图保持不变，渲染时生成新的结果图：

```text
source Image + AnnotationDocument
                  ↓
           AnnotationRenderer
                  ↓
           rendered Image
```

不要在鼠标移动时直接永久修改原始像素，否则撤销、重绘和后续 Pin 会变复杂。

## 5. 第三人：Application 集成、测试、文档与 Pin 初版

第三人负责把 F1、标注和操作条串成完整用户流程，同时维护跨模块回归测试、开发文档，并初步完成 Pin 功能。第三人的重点不是重写 F1 或标注内部实现，而是消费两者已经冻结的接口。

### 5.1 Application 集成

负责：

- 接通 `SelectionAction::Edit / Copy / Save / Pin`；
- 将 `CaptureRegion` 得到的 `Image` 传给 `AnnotationOverlay`；
- 接收标注完成回调，并将合成后的 `Image` 写回 `CaptureSession`；
- 统一处理编辑后的复制、保存和钉图；
- 处理取消、空图片、窗口关闭和保存失败等生命周期与错误路径。

核心流程：

```text
F1 框选
  ↓
Application::runCapturePipeline
  ↓
CaptureSession 保存原始 Image
  ↓
Edit → AnnotationOverlay
  ↓
AnnotationCallback 返回 rendered Image
  ↓
Copy / Save / Pin
```

建议由第三人主要负责的文件：

```text
src/app/application.cpp
include/qingying/app/capture_session.hpp
src/app/action_handlers.cpp
tests/*_integration_test.cpp
```

### 5.2 跨模块测试

至少补齐以下回归路径：

- F1 选区 → `CaptureRegion` 尺寸和像素坐标正确；
- 框选后点击复制、保存、编辑、钉图，动作分发正确；
- 标注后的结果图可以继续复制和保存；
- 标注后的结果图可以进入 Pin 窗口；
- 取消当前截图不会污染上一张结果；
- 新一次截图会清理上一轮的标注结果和 Pin 状态；
- F1、标注、操作条的已有单元测试保持通过。

测试应优先验证模块之间的输入、输出和状态变化；窗口细节仍由各模块自己的单元测试覆盖。

### 5.3 文档与验收

第三人负责维护：

- `docs/PROGRESS.md`：记录已实现、已接线、桩代码和未开始项；
- `docs/architecture.md`：更新模块边界和真实调用链；
- 本分工指南：同步三人职责、共享契约和冲突边界；
- 集成验收清单和演示步骤。

每次集成后应明确标记功能状态：

```text
Implemented：模块逻辑已实现并有测试
Wired：模块已接入 Application 用户流程
Stub：接口存在，但功能仍是桩
Not started：尚未开始
```

### 5.4 Pin 初版范围

Pin 初版只负责把最终 `Image` 显示为独立置顶窗口：

- 保持图片宽高比显示；
- 窗口可以拖动；
- 支持关闭单个 Pin 窗口和关闭全部窗口；
- 支持统计当前 Pin 数量；
- 复用现有最终图片的 Copy / Save 能力；
- F1 原图、标注结果图都可以进入 Pin。

建议接口：

```cpp
class PinManager {
 public:
  bool show(const Image& image);
  void closeAll();
  int count() const;
};
```

建议新增文件：

```text
include/qingying/pin/pin_manager.hpp
src/pin/pin_manager.cpp
include/qingying/pin/pin_window.hpp
src/pin/pin_window.cpp
tests/pin_manager_test.cpp
```

Pin 初版暂不包含：截图时排除自身、多 Pin 自动排布、标注同步、自动保存和长截图。

依赖边界：

```text
PinManager → Image
PinManager → Windows UI
PinManager ✕ CaptureEngine
PinManager ✕ AnnotationEngine 内部数据
PinManager ✕ MCP 传输层
```

## 7. 推荐集成方式

编辑按钮被点击后，Application 负责：

```text
1. dispatch(CaptureRegion)
2. 从 CaptureSession 取得 Image
3. 打开 AnnotationOverlay(Image)
4. 用户完成标注
5. AnnotationEngine::render(source)
6. 将 rendered Image 写回 CaptureSession
7. 再显示 Copy / Save / Pin 操作
```

标注编辑器的回调建议只返回结果，不直接保存：

```cpp
using AnnotationCallback =
    std::function<void(const Image& rendered_image)>;
```

这样 Copy、Save 和 Pin 仍然由应用集成层统一调度。

## 8. 开发顺序

### 第一阶段：先冻结契约

- 确认 `SelectionResult` 使用物理像素；
- 确认 `Image` 为 BGRA32；
- 确认标注坐标相对于截图左上角；
- 确认编辑完成回调返回合成后的 `Image`。

### 第二阶段：并行开发

第一人：

- 八点调整；
- 移动选区；
- DPI/多屏转换；
- F1 测试。

第二人：

- 文档模型；
- 撤销/重做；
- 矩形、箭头、画笔；
- 离屏渲染测试；
- AnnotationOverlay。

第三人：

- 核对并冻结共享契约；
- 接通 F1、标注和操作条；
- 补齐跨模块回归测试；
- 实现 PinManager 和 Pin 初版窗口；
- 更新进度、架构和演示文档。

### 第三阶段：统一集成

- 启用操作条“编辑”按钮；
- 接入 AnnotationOverlay；
- 标注完成后回到操作条；
- 验证 Copy/Save 不回归。

### 第四阶段：扩展工具

- 椭圆；
- 文字；
- 马赛克；
- 多 Pin 管理和其他高级能力；
- 更完整的编辑撤销和重做。

## 9. 冲突处理规则

1. 不在 `selection_overlay.cpp` 中实现标注绘制；
2. 不在 `annotation_engine.cpp` 中处理 Win32 消息循环；
3. 不让标注模块直接调用 `CaptureEngine`；
4. 不让标注模块直接写剪贴板或文件；
5. 同一阶段只由一个人修改 `Application::runCapturePipeline()`；
6. 共享头文件先提交契约，再分别开发；
7. 每个模块使用独立 commit，最后由第三人统一集成。

## 10. 最小可交付版本

第一轮不要一次实现所有工具，建议先完成：

- F1：八点调整 + 移动选区 + DPI 基础；
- 标注：矩形 + 箭头 + 画笔 + 撤销；
- 集成：编辑 → 标注 → 复制/下载；
- Pin 初版：最终图片置顶显示、拖动、关闭、数量统计；
- 测试：坐标转换、标注文档、撤销、渲染输出。

完成这组内容后，主演示路径就是：

```text
热键 → 框选 → 调整区域 → 编辑标注 → 复制/下载
```

Pin 初版可以作为并行验收路径：

```text
热键 → 框选 → 操作条 → 钉图 → 置顶窗口拖动 / 关闭
```
