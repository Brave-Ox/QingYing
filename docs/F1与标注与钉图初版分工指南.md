```text

  ↓
```

### 3.5 F2 窗口吸附扩展

F2 与 F1 共用 `SelectionOverlay` 的选区交互，但窗口检测、候选过滤和吸附状态应单独封装，避免把 Win32 窗口枚举逻辑散落到选区状态机中。

- 根据鼠标屏幕坐标识别当前悬停的可见顶层窗口；

标注坐标必须相对于截图左上角，而不是桌面坐标：

```text

(0, 0) ─────────────→ width
  │
  │     标注对象坐标
  │
  ↓
height
```

编辑器显示截图时可以缩放，但只在显示层做：

```text

```

### 4.5 第二人标注引擎职责

`AnnotationEngine` 不应该直接操作窗口消息，也不应该直接调用 `ActionDispatcher`。

建议职责：

```cpp
class AnnotationEngine {
 public:
  void clear();
  void add(const Annotation& annotation);
  bool undo();
  bool redo();
  Image render(const Image& source) const;
};
```

原始截图保持不变，渲染时生成新的结果图：

```text
source Image + AnnotationDocument
                  ↓
           AnnotationRenderer
                  ↓
           rendered Image
```

不要在鼠标移动时直接永久修改原始像素，否则撤销、重绘和后续 Pin 会变复杂。

### 5.5 F6 长截图方向（选框驱动，已确认）

F6 是 F1 区域捕捉流程的增强模式，不是“自动截取前台窗口全部内容”。用户在 `SelectionOverlay` 中划出的物理像素矩形是最终截图区域，后续每一帧都必须重复截取这个固定矩形。应用适配器只能验证选区并寻找滚动目标，不能把选区替换成整个客户区或整个正文区。

第一版仍只适配记事本，闭环稳定后再增加资源管理器和 Edge；不尝试支持任意应用。

#### 5.5.1 最终交互效果

```text
触发捕捉
  ↓
Application 在遮罩出现前记录目标顶层窗口
  ↓
复用 SelectionOverlay 自由划框 / 调整选区
  ↓
用户点击“长截图”
  ↓
关闭遮罩，得到 SelectionResult（物理像素）
  ↓
Application 构造 LongShotRequest
  ↓
LongShotEngine 始终截取同一个选区并驱动目标窗口滚动
  ↓
ImageStitcher 去重拼接
  ↓
最终长图写入 CaptureSession
  ↓
复用 Copy / Save / Edit / Pin
```

最终图片宽度必须等于用户选区宽度；高度由实际新增内容逐帧增长。用户选择哪一块，就只拼接哪一块，不能自动扩展为窗口宽度。

`SelectionOverlay` 会抢占前台，因此不能在遮罩关闭后通过 `GetForegroundWindow()` 猜测目标。`Application` 必须在显示遮罩前保存原前台顶层窗口句柄，并随选区一起传给长截图模块。

第一版要求选区完全位于支持应用的可滚动内容区内。如果选区包含标题栏、菜单栏、标签栏或状态栏，直接返回明确错误并提示重新选择；不要静默裁剪，也不要把固定区域重复拼入长图。

#### 5.5.2 模块职责和复用边界

复用现有捕捉链路：

```text
SelectionOverlay → SelectionResult
                         ↓
                  LongShotRequest
                         ↓
CaptureEngine.captureRegion(固定选区)
                         ↓
                  ImageStitcher
                         ↓
                   CaptureSession
```

`LongShotEngine` 负责：

- 校验目标窗口仍然存在且属于支持的应用；
- 校验用户选区完全位于可滚动内容区；
- 从已记录的目标窗口中找到接收滚轮的子窗口；
- 始终使用请求中的固定选区调用 `CaptureEngine::captureRegion()`；
- 投递一次滚动、等待内容稳定、截取下一帧并拼接；
- 在到底、没有新增内容或达到安全上限时停止；
- 失败时清空输出图片并返回稳定错误。

`LongShotEngine` 不负责：

- 显示或操作 `SelectionOverlay`；
- 调用 `GetForegroundWindow()` 决定截图区域；
- 自动选择整个客户区、正文区或窗口矩形；
- 直接修改 `CaptureSession`、复制、保存、标注或钉图；
- 重复实现 GDI/DXGI 截图；
- 在模块内部切换 DPI 感知上下文。进程级 PMv2 由 `main.cpp` 入口统一设置。

涉及 `SelectionOverlay`、工具栏和 `Application` 的接线由对应文件负责人完成，长截图开发者先提供稳定的请求接口和引擎行为，减少并行冲突。

#### 5.5.3 已确认接口

```cpp
struct LongShotRequest {
  std::uintptr_t owner_window;  // 遮罩出现前记录的目标顶层窗口
  int x;                        // 用户选区，物理屏幕坐标
  int y;
  int width;
  int height;
};

class LongShotEngine {
 public:
  explicit LongShotEngine(CaptureEngine& capture);

  ActionResult captureSelection(const LongShotRequest& request, Image& out);
};
```

接口约定：

- `request` 中的矩形是唯一截图矩形，应用配置不得覆盖；
- `owner_window` 只用于确认应用、查找内容边界和滚动目标；
- `out` 返回 BGRA32、物理像素、行优先的最终长图；
- 长截图不通过 `ActionResult.data` 传递像素；
- 请求无效返回 `ErrorCode::kInvalidArgument`；
- 应用不支持或选区不在可滚动区返回 `ErrorCode::kLongShotUnsupported`；
- 截图失败返回 `ErrorCode::kCaptureFailed`；
- 任意失败都必须清空 `out`，避免污染上一张结果。

#### 5.5.4 推荐实现顺序

1. 保留已经完成的纯图片 `ImageStitcher` 及人工图片测试。
2. 建立 `LongShotRequest` 和 `captureSelection()` 契约，暂不接 UI。
3. 新建“选区感知”的记事本配置：输入 `owner_window + 选区`，输出可滚动内容边界和滚动子窗口；禁止内部调用 `GetForegroundWindow()`。
4. 只实现一次滚动：截取选区第一帧、滚动一次、等待稳定、再次截取相同选区；暂不循环。
5. 接入 `ImageStitcher`，增加到底判断、无新增内容判断、最大帧数和最大高度。
6. 由集成者增加 `SelectionAction::LongShot` 按钮，并在 `Application` 中把预先记录的窗口与 `SelectionResult` 转成 `LongShotRequest`。
7. 记事本闭环通过后，再以独立配置增加资源管理器和 Edge。

记事本配置建议使用下面的职责，而不是返回一个自动截图矩形：

```cpp
struct LongShotProfileResult {
  std::uintptr_t scroll_target;
  int content_x;
  int content_y;
  int content_width;
  int content_height;
};

bool resolveNotepadProfile(std::uintptr_t owner_window,
                           LongShotProfileResult& out);
```

`content_*` 只用于判断用户选区是否合法，真正传给 `CaptureEngine` 的仍是 `LongShotRequest` 中的 `x/y/width/height`。

#### 5.5.5 安全限制和验收

长截图必须设置：

- 最大帧数，例如 30 帧；
- 最大输出高度，例如 30000 像素；
- 单次滚动后的稳定等待超时；
- 连续帧相同或没有新增内容时停止；
- 目标窗口失效、移动、缩放或选区不再位于内容区时立即停止；
- 失败时不修改 `CaptureSession` 中上一张有效图片。

最低验收要求：

- 选框的首帧与普通 `CaptureRegion` 对同一矩形的结果一致；
- 最终图片宽度严格等于选框宽度；
- 记事本选定区域连续滚动 2～5 屏后得到一张长图；
- 拼接处没有明显重复或断裂；
- 到达底部后自动停止；
- 选到标题栏或窗口外时拒绝执行，不自动改变选区；
- F1、F2、标注和钉图已有测试保持通过。

当前只保留与正确路线一致的文件：

```text
include/qingying/longshot/longshot_engine.hpp
src/longshot/longshot_engine.cpp
include/qingying/longshot/image_stitcher.hpp
src/longshot/image_stitcher.cpp
include/qingying/longshot/notepad_longshot_profile.hpp
src/longshot/notepad_longshot_profile.cpp
tests/longshot_engine_test.cpp
tests/longshot_stitcher_test.cpp
tests/notepad_longshot_profile_test.cpp
```

旧的“自动识别前台记事本并截取整个正文区”解析器和交互截图测试不再沿用；记事本适配应按第 3 步以选区感知接口重新实现。

当前进度：第 8 步的显式到底判断已完成。`LongShotEngine::captureSelection` 会在首帧前以及每次滚动采集后读取目标滚动子窗口的垂直滚动条状态；确认已经到达最后可见位置时停止，并保留无新增内容、最大帧数和最大输出高度这三层兜底。无法读取滚动信息时不会误判为到底。

下一小步接入 `Application` 的选区长截图入口：由调用方记录目标窗口和 `SelectionResult`，再组装 `LongShotRequest`；仍不修改 F2、标注和钉图逻辑。

## 7. 推荐集成方式

编辑按钮被点击后，Application 负责：

```text
1. dispatch(CaptureRegion)
2. 从 CaptureSession 取得 Image
3. 打开 AnnotationOverlay(Image)
4. 用户完成标注
5. AnnotationEngine::render(source)
6. 将 rendered Image 写回 CaptureSession
7. 再显示 Copy / Save / Pin 操作
```

标注编辑器的回调建议只返回结果，不直接保存：

```cpp
using AnnotationCallback =
    std::function<void(const Image& rendered_image)>;
```

这样 Copy、Save 和 Pin 仍然由应用集成层统一调度。
