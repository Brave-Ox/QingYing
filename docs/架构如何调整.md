# 轻映 QingYing — 架构如何调整

> 状态：阶段 A 的 Toolbar / Phase / 依赖收口及阶段 B 的 F3 动作回流已在当前工作区实施；后续阶段待做

## 1. 结论

现有“单 EXE + static lib + ActionDispatcher”方向保持不变。需要调整的是交互层和编排层：

1. 把 `selection_overlay.cpp` 的选区工具栏、渲染和阶段状态拆开；
2. 把多步 GUI 流程从 `Application` 收口到 `CaptureWorkflow`；
3. 明确 `Action`、`Workflow` 和表现层基础设施的边界；
4. 消除 Overlay 的嵌套消息循环；
5. F8/F9 之前再把 Action payload 和操作上下文类型化；
6. 保持 Image / CaptureSession / Engine 的现有可复用能力，不引入 Qt、插件 DLL 或第二套截图引擎。

第一批已完成：**SelectionToolbar、OverlayPhase、编辑源图上移、`overlay → capture / annotate` 依赖移除，以及标注后的 Save / Pin 回流。** 下一批优先抽 `CaptureWorkflow` / `LongShotController`，再非模态化窗口生命周期。

## 3. 从成熟截图架构借什么、不借什么

参考 KScreenGrab 等成熟截图工具时，只吸收以下模式：

- 命令描述表 + Toolbar Builder；
- 截图 UI 只上报意图，业务由上层编排；
- 窗口嗅探、拖拽选择、已选区等显式阶段；
- 全局热键与截图界面局部快捷键分离；
- 重型可选能力在确有需要时隔离。

不照搬：

- WPS 插件 DLL、wrapper、Host IPC 和独立托盘 DLL；
- Qt 与多平台抽象；
- 临时 PNG + exit code 作为内部数据总线；
- 一个 Dialog 同时拥有捕获、选区、标注、导出、Pin 和扩展能力；
- 为尚未出现的场景预先引入多进程或插件系统。

青影现有 `Image + CaptureSession + ActionResult` 比临时文件和弱类型结束码更适合当前规模，应继续保留。

## 4. 先修正架构规则

### 4.1 旧规则的问题

旧文档写过：

```text
只有 app 拥有消息循环
业务能力只经 ActionDispatcher
```

当前代码并不完全符合：

- Overlay 有嵌套模态 `GetMessage`；
- AnnotationOverlay 也有嵌套模态 `GetMessage`；
- Application 直接捕获 Overlay 背景；
- Application 在 SelectionOverlay 返回 Edit 意图后直接抓取编辑源图；
- 交互式长截图直接调用 LongShotEngine；
- GUI 文件选择后部分路径直接调用 ExportService。

### 4.2 新规则

建议冻结为：

1. **只有 app 拥有进程顶层消息泵。** 当前 Overlay / AnnotationOverlay 仍有嵌套模态循环；后续非模态化再实现该目标。
2. **外部入口只进入 ActionDispatcher 或 CaptureWorkflow。** command / mcp 不得调用 Engine。
3. **单步能力走 Action。** 例如 CaptureRegion、Copy、Save、Pin、Status。
4. **多步交互走 Workflow。** 例如 SelectRegion、EditCapture、InteractiveLongShot。
5. **表现层基础设施明确例外。** Overlay 背景快照、预览缩略图、文件对话框不是 Agent 可调用的业务 Action。
6. **Engine 不拥有 UI、Session 或外部协议。** Engine 输入明确请求，输出 Image / ActionResult / progress。

## 5. 目标结构

```text
┌────────────────────────────────────────────────────────┐
│ Application                                             │
│ Composition Root / Tray / Hotkey / Top-level Msg Pump  │
└───────────────┬───────────────────────┬────────────────┘
                │                       │
                ▼                       ▼
┌──────────────────────────┐   ┌──────────────────────────┐
│ CaptureWorkflow          │   │ ActionDispatcher         │
│ GUI 多步状态与流程       │   │ 单步、可复用业务命令     │
└───────┬──────────┬───────┘   └─────┬─────┬─────┬──────┘
        │          │                 │     │     │
        ▼          ▼                 ▼     ▼     ▼
 SelectionUI   AnnotationUI       Capture Export Pin
        │
        ▼
 LongShotController ──→ LongShotEngine ──→ CaptureEngine

CommandParser ─┐
McpBridge ─────┴──→ ActionDispatcher / 受控 Workflow 入口
```

### 5.1 Application

保留：

- 对象创建和依赖注入；
- Tray / Hotkey / SingleInstance；
- 顶层 Win32 消息泵；
- 向 Workflow 和 Dispatcher 转发入口消息；
- 应用退出总清理。

移出：

- 普通截图的大段分支；
- F3 编辑状态；
- 长截图 worker 的全部控制字段；
- 各功能的具体错误文案与状态组合。

### 5.2 CaptureWorkflow

建议职责：

```cpp
class CaptureWorkflow {
 public:
  bool beginSelection();
  void onSelectionCompleted(const SelectionResult& result);
  void onAnnotationCompleted(AnnotationResult result);
  void onLongShotControl(LongShotControl control);
  void cancel();
  void shutdown();
};
```

它拥有“当前交互流程”的状态，不拥有 GDI / DXGI 细节。依赖通过构造函数注入：

```text
ActionDispatcher
CaptureSession
SelectionOverlay
AnnotationOverlay
LongShotController
PinManager（仅捕获排除作用域或改为 CaptureFacade）
```

### 5.3 ActionDispatcher

继续用于：

```text
Status / CaptureRegion / Copy / Save / Pin
未来 CaptureWindow / CropCenter
```

不要把以下局部命令塞入 `ActionType`：

```text
选择矩形工具 / 画笔 / Undo / Redo
长截图 Pause / Resume / Stop
Toolbar hover / enable / close
```

### 5.4 LongShotController

把 Application 中以下内容集中到 app 或 longshot 上层控制器：

- worker thread；
- cancel / pause token；
- completion payload；
- progress 转发；
- join 与 shutdown；
- 一次运行只能有一个 session 的不变量。

`LongShotEngine` 继续只负责 profile、滚动、捕获、拼接和回调。

## 6. Overlay 调整

### 6.1 SelectionToolbar

选区条和标注底栏继续共用 `ModernToolbar`（GDI+ 圆角条、SVG 路径图标、中文 Tooltip）。当前工作区已将选区条的 HWND、Tooltip、绘制、命中测试和命令状态抽入 `SelectionToolbar`：

```cpp
enum class SelectionToolbarCommand {
  Copy,
  Save,
  ToggleLongShot,
  Edit,
  Pin,
  StopLongShot,
  Cancel,
};

struct SelectionToolbarItemModel {
  SelectionToolbarCommand command;
  SelectionToolbarIcon icon;
  bool enabled;
};
```

`buildSelectionToolbarItems(OverlayPhase)` 是纯状态映射，根据当前阶段计算命令和启用状态：

```text
selection valid?
longshot running?
longshot paused?
annotation available?
```

`SelectionToolbar` 只管理 HWND 和回传 `SelectionToolbarCommand`，不直接 Capture / Export / Pin；其 PIMPL 已使用 `std::unique_ptr`。

### 6.2 OverlayPhase

当前工作区已实现：

```cpp
enum class OverlayPhase {
  Sniffing,
  Creating,
  Selected,
  LongShotRunning,
  LongShotPaused,
  LongShotFinishing,
  Closing,
};
```

阶段转换集中在 `canTransitionOverlayPhase` / `transitionOverlayPhase`，拒绝非法转换：

```text
Sniffing → Creating → Selected
Sniffing → Selected                 窗口吸附
Selected → Creating                 重新框选
Selected → LongShotRunning
LongShotRunning ↔ LongShotPaused
LongShotRunning/Paused → LongShotFinishing
LongShotRunning/Paused/Finishing → Selected
任意阶段 → Closing
```

`has_hover`、当前选区、预览 Image 属于阶段数据，不应该承担阶段本身的含义。

### 6.3 OverlayRenderer

输入一个不可变快照：

```text
background Image
selection
hover rect
phase
longshot preview
```

输出用于 `UpdateLayeredWindow` 的像素。Renderer 不处理鼠标、线程或业务回调。

### 6.4 非模态化

目标接口：

```cpp
bool SelectionOverlay::show(...);  // 创建后立即返回
void SelectionOverlay::close();
bool SelectionOverlay::visible() const;
```

所有窗口消息由 Application 顶层消息泵分发。完成与取消通过回调或 app 自定义消息通知 Workflow。

迁移时要保留：

- `WS_EX_NOACTIVATE` 行为；
- Esc 临时 hotkey 注册 / 注销；
- 应用退出时不回调半成品选区；
- 长截图失败不残留 Overlay；
- owned popup 不消失的现有修复。

## 7. F3 标注已落地结构与待补边界

```text
AnnotationDocument
  ├── vector<Annotation>
  ├── undo stack
  └── redo stack

AnnotationEngine
  └── 修改 Document 的纯逻辑命令

AnnotationRenderer
  └── source Image + Document → rendered Image

AnnotationOverlay
  └── Win32 输入 / 预览 / 局部工具栏
```

当前已由 `qingying_annotate` 编译目标提供上述结构。`SelectionOverlay` 的 Edit 按钮只上报意图，Application 在 Overlay 返回后抓取源图并打开编辑器；确认后把 `SelectionResult.annotated_image` 写入 `CaptureSession`、自动 Copy、合成桌面预览，并以 `initial_selection` 恢复同一选区的 Save / Pin / Edit 操作条。

约束：

- 标注坐标相对于 Image 左上角；
- 原始 Image 不随鼠标移动被永久改写；
- 取消不覆盖 CaptureSession；
- 提交返回 `AnnotationFinishResult`；
- Application / Workflow 决定是否把 rendered Image 写回 Session；
- Copy / Save / Pin 不知道 AnnotationDocument。

当前仍待补：重做按钮，以及 Copy / Save / Pin / 再编辑在真实窗口、双屏和混合 DPI 下的组合验收。

结果操作条恢复期间选区保持只读，确保 `SelectionResult` 的物理矩形与 `annotated_image` 尺寸始终一致；若开始长截图，则显式丢弃标注栅格并切换到长截图结果语义。

## 8. Action 契约调整

### 8.1 近期不改大接口

阶段 A / B 的第一批实现刻意不重写 `ActionRequest`，避免把结构收敛与 F8/F9 契约同时扩大。当前保持：

- GUI Save 的文件对话框与保存调用仍由 Application 管理，后续可再统一到 Save Handler；
- 明确桌面背景快照是 presentation 调用；
- `LongShotRegion` 暂时标注“未注册 / 保留”，不要假装已经统一分发。

### 8.2 F8/F9 前类型化

推荐 `std::variant` 或命名 payload。目标是让无效字段组合无法构造，而不是单纯换语法。

外部入口还需要：

- request id；
- operation id（异步交互）；
- cancellation；
- schema validation；
- 明确“当前结果”与指定结果的选择；
- 主线程调度与超时。

### 8.3 CaptureSession 边界

GUI 继续保留 Session 的“当前图”语义。MCP 不直接拿全局 Session 指针，而通过受控 Action / ResultStore：

```text
capture action → capture_id
copy/save/pin(capture_id or current)
```

是否引入 ResultStore 等到 F9 设计时决定，不在当前 F3 回流补丁中提前实现。

## 13. 文档同步规则

每次功能提交后按以下口径更新：

- **Implemented**：模块逻辑存在且有自动测试；
- **Wired**：已经进入用户可触发的 Application / Workflow；
- **Manually verified**：真实窗口、DPI 或交互已按步骤验收；
- **Stub**：接口存在但固定返回空、false 或 `kNotImplemented`；
- **Not started**：没有接口或实现。

进度文档不得把 Implemented 自动等同于 Manually verified，也不得仅凭提交标题标记完成。

## 14. 最终判断

青影现在不缺新的“大架构”，缺的是继续把 UI 工作流收口。Toolbar / Phase、编辑源图上移和标注后 Save / Pin 回流已经用小步改造完成，271 个执行测试保持全绿。下一步先做真实 GUI 验收，再抽 CaptureWorkflow / LongShotController 并非模态化；最后设计 F8/F9 的异步外部契约，避免把 Application 当前的顺序编排固化成 MCP 公共接口。
